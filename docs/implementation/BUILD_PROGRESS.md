- **Real bug in the reply-wait fix itself**: `followAlwaysEdge()` moved `current_node_id` forward to the *next* node right after sending a message, then returned to "wait" — but `resumeScriptRunAfterFanReply()` decides whether to resume by checking the *current* node's type, and it was already looking at the next node (often `paid_media`), so it correctly refused to advance on a plain reply and the run looked permanently stuck. Fixed: `current_node_id` now stays on the node that was just sent; resuming explicitly steps the pointer forward before calling `advanceScriptRun()` again. Owner confirmed working after this fix.
